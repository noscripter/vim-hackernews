BASIC USAGE                                     *hackernews-usage*

* Open the Hacker News front page in Vim by executing the `:HackerNews` command
* The HackerNews command takes an optional parameter to view lists other
  than the top stories on the front page:
    * `:HackerNews ask`
    * `:HackerNews show`
    * `:HackerNews jobs`
    * `:HackerNews best`
    * `:HackerNews newest`
* Press lowercase `o` to open links in Vim
* Press uppercase `O` to open links in default web browser
* Numbered lines with story titles on the front page link to the story url
* Comment lines on the front page link to the comments url
* Press uppercase `F` to fold current comment thread
* Press lowercase `u` to go back
* Press `Ctrl+r` to go forward
* Execute the `:bd` command to close and remove the Hacker News buffer


CONFIGURATION

* `g:hackernews_show_progress`
  - When set to `1` (default), the plugin shows short progress messages while
    fetching stories/items and building comment trees. Messages appear in the
    command area and in `:messages`.
  - Set to `0` to silence progress messages.

* `g:hackernews_max_items`
  - Maximum number of stories fetched for the current list. Defaults to `60`
    for `news/newest/best` and `30` for others. Set to a lower value if your
    connection is slow, or a higher value if you want more items.

* `g:hackernews_concurrency`
  - Number of parallel requests used when fetching story details from the
  official API. Default `12`. Increase to speed up on fast networks; lower on
  slower or rate-limited networks.


PERFORMANCE

- Official API returns lists of IDs. The plugin fetches story details in
  parallel using a small thread pool (default 12) to reduce total latency.
- Output preserves the original order of the ID list.
- Progress messages are printed periodically (every ~10 items) if
  `g:hackernews_show_progress` is enabled.
- Comment trees are fetched recursively with internal depth/node limits to
  prevent pathological timeouts on very large threads. Progress for the
  top-level comment fetch is shown when enabled.
- Tuning knobs:
  - `g:hackernews_max_items` caps how many stories are displayed for a list.
  - `g:hackernews_concurrency` adjusts how many parallel HTTP requests are used.
  - Reduce these values if you experience timeouts; increase on fast networks.


TIPS

- Slow connection / VPN:
  - `let g:hackernews_max_items = 30`
  - `let g:hackernews_concurrency = 6`

- Typical Wi‑Fi:
  - `let g:hackernews_max_items = 60`
  - `let g:hackernews_concurrency = 12`

- Fast wired / powerful desktop:
  - `let g:hackernews_max_items = 90`
  - `let g:hackernews_concurrency = 24`


ENHANCED MOTIONS                                *hackernews-motions*

Uppercase `J` and `K` are mapped to helpful new motions based on what type of
content is on the screen:

* Move to next/prev item when viewing the front page. (If the cursor is on a
  numbered line with story title the cursor will move to the next/prev numbered
  line with story title. If the cursor is on a comment line it will move to the
  next/prev comment line.)
* Move to next/prev comment when viewing comments.
* Move to next/prev paragraph when viewing the text version of articles.


COMMANDS                                        *hackernews-commands*

:HackerNews             Open Hacker News front page stories in Vim

Network notes:
- The plugin uses the official Hacker News Firebase API for all requests
  (stories, items, comments). This removes the dependency on third-party
  services and improves reliability. Fetching comment trees may take longer
  than story lists due to the number of requests involved.
